# Автобэкап на Google Диск + автоперезапуск сайта — настройка на VPS

Всё ниже выполняется по SSH на самой VPS (можно прямо из Termux — `ssh
root@ваш_ip`), не в Termux локально.

## Шаг 1. Поставить rclone (умеет заливать файлы на Google Диск)

```
curl https://rclone.org/install.sh | sudo bash
```

## Шаг 2. Подключить Google Диск к rclone

```
rclone config
```
Дальше отвечаете на вопросы:
1. `n` — новый remote (new remote)
2. Имя: **gdrive** (именно так — скрипт бэкапа ожидает это имя; если хотите другое — поправьте `GDRIVE_REMOTE` в `scripts/backup-to-drive.sh`)
3. Storage: находите в списке **Google Drive** (обычно номер, например `18` — цифра зависит от версии rclone, ищите по названию)
4. `client_id` и `client_secret` — просто нажмите Enter (пусто), rclone использует свои
5. `scope` — выберите `1` (полный доступ к Диску)
6. `root_folder_id`, `service_account_file` — Enter (пусто)
7. `Edit advanced config?` — `n`
8. `Use auto config?` — здесь **на VPS без графического браузера отвечайте `n`**.
   rclone покажет команду вида:
   ```
   rclone authorize "drive"
   ```
   Скопируйте её, вставьте в Termux **на телефоне** (или в любой компьютер с браузером, где есть rclone — `pkg install rclone` в Termux тоже ставится), выполните, откроется ссылка на вход в Google-аккаунт в браузере телефона. После входа rclone на телефоне выведет длинную строку с токеном — скопируйте её целиком и вставьте обратно в терминал VPS, туда, где он её ждёт.
9. `Configure this as a Shared Drive?` — `n` (если это не общий корпоративный Диск)
10. `y` — подтвердить, `q` — выйти из конфигуратора

Проверка, что всё подключилось:
```
rclone lsd gdrive:
```
Должен показать список папок на вашем Google Диске (или пустой вывод, если Диск пустой — это тоже нормально, значит подключение работает).

## Шаг 3. Создать папку для локальных бэкапов

```
mkdir -p /backup
```
(Скрипт сам её создаст при первом запуске, если забудете — но лучше сразу.)

## Шаг 4. Проверить скрипт бэкапа вручную

```
cd /root/alem-mod
sh scripts/backup-to-drive.sh
```
Смотрите на вывод — должно быть «Архив создан...», «Загружено на Google
Диск.», «Готово.». Проверьте `/backup/` (`ls -lh /backup/`) и сам Google
Диск (`rclone lsf gdrive:alem-mod-backups`) — файл должен появиться в обоих
местах.

## Шаг 5. Расписание — cron

Открываем crontab (для root, раз проект в `/root/alem-mod`):
```
crontab -e
```
Добавляем строки (если спросит редактор — можно выбрать `nano`, это проще):
```
# Часовой пояс для расписания ниже — чтобы 4 утра было именно по Москве,
# независимо от того, в каком поясе настроена сама VPS.
TZ=Europe/Moscow

# Бэкап каждые 12 часов (в 00:00 и в 12:00 по времени, заданному TZ выше)
0 */12 * * * /bin/sh /root/alem-mod/scripts/backup-to-drive.sh >> /var/log/alem-mod-backup.log 2>&1

# Перезапуск сайта каждый день в 4:00 утра по Москве
0 4 * * * /usr/bin/pm2 restart alem-mod >> /var/log/alem-mod-restart.log 2>&1
```
Сохраняете, выходите — cron подхватит сам, перезапускать ничего не надо.

**Важно про путь к pm2**: команда `/usr/bin/pm2` — это самый частый путь, но
у вас может быть другой (если Node ставили через nvm, например). Проверьте
командой:
```
which pm2
```
и подставьте то, что она покажет, вместо `/usr/bin/pm2` в строке выше — в
cron (в отличие от обычного терминала) переменная PATH урезанная, короткое
`pm2 restart alem-mod` без полного пути может просто не найтись.

## Проверка, что всё работает

Логи обеих задач — по расписанию, а не только при ручном запуске:
```
tail -f /var/log/alem-mod-backup.log
tail -f /var/log/alem-mod-restart.log
```
Через 12 часов и на следующий день в 4:00 в этих файлах должны появиться
новые строки. Список файлов сейчас:
```
ls -lh /backup/
rclone lsf gdrive:alem-mod-backups
```
В обоих местах не должно накапливаться больше 4 файлов — при пятом самый
старый исчезает сам.

## Восстановление из такого бэкапа

Это обычный `.tar.gz` всей папки проекта (без node_modules и .git). Чтобы
восстановить:
```
cd /root
mv alem-mod alem-mod-old   # на всякий случай, а не сразу удалять
tar -xzf /backup/alem-mod-backup-ДАТА.tar.gz -C /root
cd alem-mod
npm install
pm2 restart alem-mod
```
Либо — раз данные (база + загрузки) всё равно внутри этого архива — можно
воспользоваться и встроенным в сайт восстановлением: распакуйте архив во
временную папку, найдите там `data/modbuild.db` и `public/uploads/`, из них
соберите .zip именно в том формате, который ждёт `/admin/settings` (кнопка
«Восстановить») или `data/restore-inbox/` — так изменения применятся без
остановки сайта. Для простого «откатить всё как было» проще и надёжнее
первый способ (полная замена папки).
